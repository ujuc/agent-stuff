# CLAUDE.md — skills

Skill definitions for Claude Code. Each skill is `SKILLNAME/SKILL.md` with optional `references/` and `scripts/` / `tools/` directories for bundled assets.

## Work Rules

- Follow the frontmatter spec at `generate-skills/references/frontmatter-spec.md` for all skill metadata
- Skill body text is English; only `description` / `when_to_use` and user-visible trigger phrases may contain Korean
- When modifying a skill, update `README.md` if the skill's purpose, triggers, or model assignment changed
- After editing a skill, run `skill-improver` on the affected targets before committing — it validates frontmatter, spec conformance, and scenario coverage
- Every SKILL.md frontmatter MUST include a `group:` field — one of: `planning`, `analysis`, `build`, `verify`, `docs`, `writing`, `llm`, `meta`. `validate-skill` fails when it is missing or outside the list (`generate-skills/tools/skill-core/src/rules.rs::ALLOWED_GROUPS`), and the group map in `README.md` must list the skill under the same slug or the catalog falls out of sync.

## Behavioral Guidelines

- `learned/` is auto-generated by external plugins — do not track; add `claude/skills/learned/` to `../../.gitignore` if it starts persisting files
- Do not duplicate skill logic across skills; extract shared patterns into `references/` files owned by the authoritative skill, and cross-link instead of copying
- The 4 harness component skills plus a generator stage (`spec-planner` → `sprint-contract-negotiator` → generator stage → `qa-evaluator` / `frontend-design-evaluator`) form a pipeline orchestrated by `multi-agent-orchestrator` — a change in any stage can break downstream contracts

## Conventions

- **Model assignment rationale**: `opus` for planning, orchestration, and spec expansion; `sonnet` for deterministic execution; `haiku` for mechanical rendering with no judgment; `sonnet + advisor` when the skill needs a second-opinion review loop (add `advisor` to `allowed-tools`). Blind independent review subagents run `model: sonnet` and consult `advisor()` — opus-backed per `settings.json` `advisorModel` — for a cross-model second opinion on low-confidence findings; advisor forwards only the reviewer's own transcript (the generated files), so the review stays blind
- **`disable-model-invocation: true`** for invasive skills (multi-file writes, long autonomous sessions — currently `generate-skills`); restricts auto-invocation so only explicit slash commands and Skills-table triggers fire. `multi-agent-orchestrator` permits auto-invocation but enforces a Stage 0 user-confirmation gate before running the pipeline.
- **Shared artifact directories** created/consumed by skills: `.plans/plan-*.md` (`annotate-plan`, `implement-plan`), `.research/research-*.md` (`deep-read`), `.sprint/contract.md` (`sprint-contract-negotiator`), `spec.md` (`spec-planner`)
- **Chrome-dependent skills** (`qa-evaluator`, `frontend-design-evaluator`) use MCP deferred tools — schemas must be loaded via `ToolSearch` at skill start. Listing tool IDs in `allowed-tools` only pre-grants permission; the schema still requires a `ToolSearch` call to become callable
- **Periodic invocation**: `skill-improver` is driven by the SessionStart hook `~/.claude/hooks/skill-improver-cadence.sh` (7-day cadence, consent-gated) — do not additionally register it via cron
